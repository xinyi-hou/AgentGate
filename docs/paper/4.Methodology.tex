\section{AgentGate系统设计与实现}
\label{sec:methodology}
% ============================================================

本章面向智能体与外部工具的运行时交互过程，设计工具调用安全网关AgentGate。系统位于智能体
生成结构化工具请求到目标工具实际执行之间，将框架特有调用转换为统一安全事件，增量构建
Agent Transition Graph（ATG），并在高风险调用产生真实副作用前完成状态化检测与控制。系统
不依赖Prompt、思维链或完整模型Trace，其保护范围仅覆盖经AgentGate路由的结构化工具调用。

AgentGate借鉴Reference Monitor的完全仲裁思想、Falco/Tetragon的事件--条件--动作模型、
EQL/CEP的时序关联、information-flow control与taint tracking的数据标签、provenance-based
intrusion detection的来源关系以及SIEM的窗口聚合。与MalSkills相似，系统将安全敏感操作抽取、
依赖图和符号优先的神经符号推理分离；不同之处在于AgentGate分析真实运行时事件，并要求在
危险sink执行前给出控制动作。

\subsection{总体架构与运行流程}
\label{subsec:architecture}

AgentGate包含三个核心模块：工具调用安全语义抽象、运行时ATG构建，以及基于图的状态化风险
检测与运行时控制。一次工具交互的完整流程表示为
\begin{equation}
\begin{aligned}
c_t &\xrightarrow{\mathcal{C}} \hat{c}_t
\xrightarrow{\mathcal{N}} e_t^{req}
\xrightarrow{\mathcal{G}_{preview}(G_{t-1})} \Delta G_t^{cand}\\
&\xrightarrow{\mathcal{F}(G_{t-1},\Delta G_t^{cand},P)} d_t
\xrightarrow{\mathrm{enforce}} r_t
\xrightarrow{\mathcal{N}} e_t^{res}
\xrightarrow{\mathcal{G}_{commit}} G_t,
\end{aligned}
\label{eq:atg-runtime}
\end{equation}
其中$c_t$为框架原始调用，$\hat{c}_t$为统一Canonical Tool Call，$e_t^{req}$与$e_t^{res}$
分别为请求和结果安全事件，$G_{t-1}$为已经提交的ATG，$\Delta G_t^{cand}$为不落库的候选图
扩展，$P$为策略，$d_t$为运行时决策。只有工具真实执行后，结果事实才进入$G_t$。

系统支持\textsc{Allow}、\textsc{Audit}、\textsc{Restrict}、\textsc{Approve}和
\textsc{Block}五种动作，并按单调优先级合并多个检测结果。参数限制只能收缩原调用能力，且
收缩后必须重新完成事件实例化和检测；审批结果与主体、会话、调用、工具及有效参数摘要绑定。

\subsection{工具调用安全语义抽象}
\label{subsec:event-abstraction}

\subsubsection{统一工具调用表示}

不同框架的函数调用、MCP \texttt{tools/call}与Sidecar请求首先由Adapter转换为
Canonical Tool Call：
\begin{equation}
\hat{c}_t=\langle I_t,T_t,A_t,\tau_t,S_t,M_t\rangle,
\label{eq:canonical-call}
\end{equation}
其中$I_t$包含调用、主体、Agent、会话、任务和父调用标识，$T_t$为工具标识与名称，$A_t$
为结构化参数，$\tau_t$为运行时时间，$S_t$为来源框架与传输方式，$M_t$为不影响安全结论的
扩展元数据。Canonical层不包含风险、恶意性或放行结论。可信Adapter提供的身份与任务上下文
覆盖普通调用参数，防止Agent自行扩大作用域。

当前实现支持进程内function、LangGraph、OpenAI Agents风格回调、自研HTTP Sidecar，以及
MCP STDIO和Streamable HTTP代理。各接入方式只负责协议转换和完整仲裁，后续模块不感知原始
框架。

\subsubsection{工具能力与混合语义抽取}

对工具$T$定义静态安全能力画像
\begin{equation}
P_T=\langle O_T,R_T,B_T,D_T,E_T,K_T,Q_T\rangle,
\label{eq:tool-profile}
\end{equation}
其中$O_T$为可能操作，$R_T$为资源类型，$B_T$为资源、范围、目的地和payload参数绑定，$D_T$
为输入输出数据类型，$E_T$为潜在副作用，$K_T$为输出信任属性，$Q_T$记录来源、字段证据与
置信度。操作集合为READ、WRITE、SEND、EXECUTE、DELETE、AUTH、PRIVILEGE和INSTALL。

画像生成采用三级策略：显式配置优先；其次根据名称、描述、输入输出Schema和annotations执行
确定性规则；当没有候选、存在多个候选或工具语义过于通用时，才调用可选LLM Semantic
Resolver。Resolver只返回操作、资源、字段绑定、数据类型、副作用、置信度和证据等严格Schema
事实，不能产生执行决策。高影响工具在语义仍不确定时失败关闭，要求显式画像。该设计借鉴
MalSkills将安全敏感操作提取与恶意性判断分离的思想，并避免让LLM成为每次调用的必经路径。

\subsubsection{安全事件实例化}

模块将画像与本次参数和可信上下文绑定：
\begin{equation}
e_t=\mathcal{I}(P_{T_t},A_t,C_t)
=\langle I_t,O_t,R_t,V_t,D_t,Z_t,X_t,Q_t\rangle,
\label{eq:tool-security-event}
\end{equation}
其中$O_t$为实际操作，$R_t$为资源、标识与作用范围，$V_t$为结构化operand，$D_t$为输入输出
数据对象与类型，$Z_t$为目的地及信任域，$X_t$为外部、持久、权限和破坏性影响，$Q_t$为
置信度、来源和信任证据。操作、资源、operand和数据对象分别建模，例如邮件发送的操作为
SEND、资源为MESSAGE、operand为body和附件字段、目的地为recipient，而DataObject表示此次
实际消费的数据。

请求事件描述拟执行行为，用于执行前判断；结果事件结合真实返回记录成功状态、实际数量、
输出信任和新数据对象。被阻断的请求不会生成已经发生的结果事实。

\subsection{运行时Agent Transition Graph构建}
\label{subsec:atg}

\subsubsection{图模式与作用域}

ATG是带类型、方向、属性和时间的property graph，而非树。系统按主体与会话分区物理图，
节点和边继续携带任务与Agent标识。single-agent、multi-tool和multi-agent执行共享同一Schema；
多Agent并不使用独立状态结构，而是由Agent节点、委托边和跨Agent数据边表达。

图包含五类节点：
\begin{itemize}
    \item \textbf{AgentNode}：主体、Agent、会话、任务和角色；
    \item \textbf{ToolEventNode}：调用、工具、操作、阶段、状态、影响和时间；
    \item \textbf{ResourceNode}：文件、数据库、进程、配置等实际资源；
    \item \textbf{DataObjectNode}：数据类型、标签、来源、生产者和内容指纹；
    \item \textbf{TrustDomainNode}：内部、可信外部或未知外部目标。
\end{itemize}

图包含九类有向边：NEXT表示同任务同Agent的事件顺序，PERFORMS连接Agent与调用，OPERATES\_ON
连接调用与资源，PRODUCES和CONSUMES表示调用的数据输出输入，DERIVES\_FROM表示派生对象来源，
TARGETS连接调用与信任域，PARENT\_OF表示父子调用，DELEGATES\_TO表示跨Agent委托。NEXT仅是
时间证据，不能替代CONSUMES和DERIVES\_FROM所表达的数据依赖。

\subsubsection{标签与轻量来源跟踪}

对于安全相关READ或WRITE结果，系统创建数据对象
\begin{equation}
d=\langle id,type,label,source,producer,fingerprint\rangle.
\label{eq:data-object-atg}
\end{equation}
标签分为敏感类别（SENSITIVE、CREDENTIAL、SECRET、PERSONAL、FINANCIAL和INTERNAL）、信任
与来源（TRUSTED、UNTRUSTED、INTERNAL/EXTERNAL\_ORIGIN）以及制品属性（PERSISTENT、
CONFIGURATION和EXECUTABLE）。初始标签由结果数据类型、信任域和内容证据生成；若WRITE消费
已有对象并产生新对象，标签沿DERIVES\_FROM继承。

确定性依赖恢复综合对象标识、规范化精确值、包含关系、文件路径、摘要以及URL/Base64等简单
变换。复杂转换无法确定时，可选LLM Dependency Resolver只对同一任务的有界候选对象判断
来源关系，并返回对象标识、关系布尔值、置信度和理由。只有对象真实存在且置信度超过阈值时
才接受该关系。该机制不声称实现任意程序语句级动态污点分析。

\subsubsection{候选图与提交图}

REQUEST只生成候选扩展$\Delta G_t^{cand}$，供检测器与$G_{t-1}$联合查询，不写入Graph Store。
因此BLOCK和审批等待不会污染后续历史。SUCCESS RESULT重新构造并提交Graph Delta，创建真实
资源、目标、数据对象和来源边。FAILED RESULT可保留FAILED ToolEvent及执行主体、时间或委托
审计边，但不记录资源、目标、数据和成功副作用关系。

内存实现使用会话TTL与互斥锁；Redis实现使用稳定graph key、WATCH/MULTI乐观更新和跨实例
会话锁。事件操作、任务、数据标签、任务、指纹、最近上下文以及入边/出边均建立索引，使在线
检测无需每次扫描完整图。

\subsection{基于图的状态化风险检测与运行时控制}
\label{subsec:graph-detection}

对候选请求，风险函数为
\begin{equation}
\rho_t=\mathcal{F}(G_{t-1},\Delta G_t^{cand},P,A_u),
\label{eq:graph-risk}
\end{equation}
其中$A_u$为可选可信任务授权。普通Agent只能提供任务标识，不能上传一份自行声明的授权对象。

\subsubsection{符号优先的图规则}

当前图规则重点检测以下模式：
\begin{align}
&Data[SENSITIVE]\xrightarrow{CONSUMES}SEND[UNKNOWN\_EXTERNAL],\\
&Data[CREDENTIAL]\xrightarrow{CONSUMES}AUTH,\\
&Data[UNTRUSTED]\xrightarrow{CONSUMES}EXECUTE/INSTALL,\\
&READ[EXTERNAL]\rightarrow WRITE[ARTIFACT]\rightarrow EXECUTE.
\end{align}
规则检查当前sink、消费对象标签、任务/Agent作用域以及DERIVES\_FROM来源路径。若同一任务只是
先读取不可信内容、后执行高影响操作，但没有直接数据或控制依赖，系统将其视为较弱时间证据并
要求审批，而非形成高置信来源阻断。由此可区分“曾读取敏感数据后发送无关公开文本”和“实际
发送该敏感数据”两种行为。

累计读取检测通过operation/task索引在事件时间窗口内计算已成功数量与当前请求预计值。跨Agent
外泄不需要专门规则：同任务不同Agent消费同一或派生DataObject时，普通敏感sink规则即可匹配，
而DELEGATES\_TO和PARENT\_OF提供额外编排证据。

\subsubsection{选择性LLM关系证据}

只有确定性依赖仍模糊时，系统才可向Graph Risk Resolver提供同任务的有界局部子图和去除原始
参数/结果的候选事件。Resolver返回关系是否成立、风险类型、证据节点、置信度和解释，不返回
ALLOW或BLOCK。当前实现只把其高置信输出作为AUDIT证据，最终阻断仍由显式图边、标签和策略
产生，并记录LLM调用原因与耗时。

\subsubsection{控制语义与可解释证据}

检测结果按
\begin{equation}
ALLOW<AUDIT<RESTRICT<APPROVE<BLOCK
\end{equation}
合并。决策记录匹配规则、事件、数据对象、图节点、图边、传播标签及关系证据。研究模式提供
会话图和决策局部证据接口，可按任务、Agent和时间过滤，且不返回数据内容指纹。

系统仍保留旧SessionSecurityState和RuleMatchState作为已有实验与API的兼容镜像，但ATG是新
运行时检测的权威历史表示。该原型不覆盖绕过网关的shell、网络、文件或系统调用，也不将
Redis研究存储声明为生产级分布式事务或高可用系统。

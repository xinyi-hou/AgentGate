\section{引言}
\label{sec:introduction}

大语言模型（Large Language Models, LLM）在复杂推理与工具调用能力上的进展，使智能体系统得以突破对话交互的边界，进入任务执行的新阶段。借助工具调用机制，智能体可接入外部API、数据库、文件系统与业务平台等异构资源，完成数据分析、流程自动化、系统运维等复杂任务。ReAct~\cite{yao2023ReAct}、Toolformer~\cite{schick2023Toolformer}等工作确立了“推理—执行”的智能体范式，为工具调用能力的规模化应用奠定了基础；模型上下文协议（MCP）等标准化交互规范的提出~\cite{anthropic2025MCP}，进一步统一了工具描述、能力发现与调用流程，推动工具生态向开放化、组件化方向快速演进。然而，随着大量第三方工具、外部数据源与后端系统被纳入智能体执行链路，基于静态白名单与固定权限的传统信任机制已难以适配开放生态的动态性，工具调用全链路的运行时安全风险日益凸显。

工具调用在拓展智能体行动边界的同时，也将大模型的安全风险从内容生成层传导至真实业务系统层。OWASP Agentic AI Security Top 10 已将工具滥用、目标劫持、供应链风险以及权限控制等问题列为智能体应用面临的核心安全威胁~\cite{owasp_agentic_ai_2026}。一条完整的调用链路横跨用户、智能体、工具服务与后端资源多个信任域，调用请求、元数据与执行结果在不同域间持续流转，任一环节的不可信输入都可能沿链路扩散，形成双向安全威胁：一方面，恶意或被篡改的工具可通过污染描述文本、在返回结果中嵌入提示注入指令等方式，劫持智能体决策逻辑，引发指令覆盖、上下文污染、记忆篡改与信息窃取等问题；另一方面，被注入控制的智能体、配置不当的客户端也可能生成偏离用户意图与授权范围的调用请求，造成越权访问、危险命令执行、批量数据导出与业务状态篡改，直接威胁后端系统与核心数据安全。


大模型智能体已具备工具调用、任务规划和自主执行能力，其安全边界随之从模型输出层扩展至智能体与外部系统交互的完整执行链路。现有研究从提示注入防护、工具安全分析与权限控制等角度开展了探索，但仍存在三方面不足。
其一，现有防护多聚焦单一交互环节，缺乏覆盖工具调用全生命周期的统一视角。智能体侧方案（如AgentArmor~\cite{wang2025AgentArmor}、DRIFT~\cite{li2025DRIFT}）主要检测工具返回内容中的间接提示注入，通常假设智能体生成的调用请求本身可信，难以判断调用是否符合当前任务目标。传统API安全机制则依赖身份认证与静态权限，仅验证主体是否具备调用资格，无法判断当前任务是否允许具体操作。
其二，现有方法缺乏面向任务语义与调用实际影响的细粒度判断能力。工具调用的安全性不仅取决于接口是否合法，还与任务目标、访问资源、操作范围及潜在副作用密切相关——同一查询接口既可用于单条读取，也可经参数变化演化为批量导出。基于规则匹配或静态策略的方法难以捕获此类语义偏差。Progent~\cite{shi2025Progent}、AgentSpec~\cite{wang2026AgentSpec}、Pro2Guard~\cite{wang2025Pro2Guard}等工作虽从权限规范与主动防护角度取得进展，但仍缺少对任务意图、工具能力与调用效果的统一建模，难以支撑动态授权决策。其三，现有机制普遍缺乏跨调用状态感知能力，难以识别多个合法操作组合形成的链式风险。实际攻击往往通过多工具协同逐步完成：先读取敏感信息，再借助其他工具外传，或通过多次小范围访问累积形成批量泄露。无状态的单次请求检测无法感知调用间的数据依赖与行为演化。

因此，智能体工具调用安全需要从单点检测转向面向完整执行链路的运行时治理，在统一表示工具能力、任务约束与执行状态的基础上，实现内容可信性、调用授权性与跨调用风险的协同管控。
针对上述问题，本文提出面向智能体工具调用链路的运行时安全网关AgentGate。不同于针对单一输入或单次调用的防护方案，AgentGate以经过网关的结构化工具调用为保护对象，通过统一安全表示与状态感知机制实现跨信任域的动态安全控制。AgentGate包含三个核心机制：一是工具调用安全事件抽象，将异构调用归一化为操作、资源、数据、目的地与影响等安全事实；二是会话安全事实维护与轻量数据来源跟踪，仅从真实执行结果增量维护标签、计数和敏感对象；三是状态化风险检测与运行时控制，结合独立序列状态和可信任务授权发现单次合法但组合产生危害的跨调用攻击链。
AgentGate的原型实现、实验数据与复现脚本已开源：\url{https://github.com/xinyi-hou/AgentGate}。本文主要贡献如下：

\begin{itemize}

\item \textbf{面向工具调用全链路的威胁模型。}
面向智能体工具调用链路，系统分析不可信工具内容、智能体生成调用以及多步执行中的风险传播机制，建立覆盖工具内容污染、任务范围外调用与跨调用数据泄露的统一威胁模型，明确攻击者能力、信任边界与安全目标，为运行时防护机制设计提供基础。

\item \textbf{统一内核的运行时安全网关AgentGate。}
设计并实现面向智能体工具调用链路的运行时安全网关，通过统一安全事件对工具能力和调用实际效果进行建模，提出会话事实与轻量来源跟踪、独立序列状态和执行前控制机制，提供放行、审计、限域、人工确认与阻断五类处置能力。

\item \textbf{系统化实验评估。}
基于InjecAgent和TS-Bench AgentDojo-Traj两个公开基准的5436个判定样本，以及8个协议原生来源重放用例，分别评估内容检测、任务授权和跨调用状态机制。结果表明，确定性内容检测在InjecAgent配对样本上取得82.23\%的F1和0误报，但对无统一攻击前缀的base设置仍存在明显漏报；任务契约将AgentDojo-Traj的漏报率由静态操作权限的19.60\%降至6.82\%，同时使误报率由21.43\%升至34.33\%，揭示了当前最小权限编译在安全性与任务效用之间的真实权衡。

\end{itemize}


本文的章节安排如下：第\ref{sec:background}章回顾智能体工具调用技术的发展历程与现有安全防护研究；第\ref{sec:threadmodel}章结合典型攻击场景，建立威胁模型，明确攻击者能力、信任边界与三类核心安全风险；第\ref{sec:methodology}章阐述AgentGate的系统设计与实现，包括统一安全表示、三项核心安全机制及运行时处理流程；第\ref{sec:evaluation}章分别评估内容安全、任务授权、状态化检测与本地运行开销；第\ref{sec:discussion}章讨论系统的适用边界、当前局限与未来研究方向；第\ref{sec:conclusion}章总结全文工作。

\section{实验评估}
\label{sec:evaluation}

本章从公开任务上的端到端结果、状态化检测机制、风险场景覆盖、运行时开销和语义模型稳定性五个方面评价AgentGate。实验只将能够在结构化工具执行边界观测和控制的行为纳入有效性分析。对于具有危险副作用真值的任务，只有在副作用发生前留下限制、审批或阻断证据，才记为AgentGate成功防护；仅有最终结果变化而没有网关控制证据时，不将变化归因于AgentGate。本文回答以下五个研究问题：

\hangindent=2.5em\hangafter=1
\textbf{RQ1（端到端结果与防护归因）：}
在具有明确工具调用的公开任务上，AgentGate如何改变攻击结果和正常任务效用，其中多少改善具有实际网关控制证据？

\hangindent=2.5em\hangafter=1
\textbf{RQ2（状态化检测机制）：}
单事件、调用时序、ATG数据来源和标签传播分别对防护效果产生何种影响？

\hangindent=2.5em\hangafter=1
\textbf{RQ3（风险场景与留出扰动）：}
AgentGate能否处理不同安全操作链，并在Agent内部数据变换和信任配置漂移条件下保持有效？

\hangindent=2.5em\hangafter=1
\textbf{RQ4（运行时开销与扩展性）：}
AgentGate的同步分析开销如何随调用数量和ATG规模增长？

\hangindent=2.5em\hangafter=1
\textbf{RQ5（语义模型稳定性）：}
切换不同语义模型时，结构化解析、最终安全结果、Token和延迟有何变化？


\subsection{实验设置}
\label{subsec:evaluation-setup}

\textbf{运行环境。}
实验对应AgentGate 0.6.0和Python 3.12.3，运行于Linux 6.8服务器。服务器包含两颗AMD EPYC 9554处理器、128个物理核心和503\,GiB内存。除RQ5外，任务模型和语义模型均为DeepSeek-V4-Pro-0813，温度为0。API地址和密钥只从\texttt{.env}读取，不写入实验产物。AgentDojo、Agent-SafetyBench、MCP-SafetyBench和MCP-Bench分别固定在commit \texttt{089ed468c}、\texttt{74feea8}、\texttt{7872437}和\texttt{7a8eaea}。

\textbf{冻结样本协议。}
样本清单在运行AgentGate之前生成，公开子集manifest的SHA-256为\texttt{07b902df650c51fc}，MCP清单的SHA-256为\texttt{d3211799cc0734b9}。表~\ref{tab:benchmark-matrix}给出本次协议。AgentDojo正类是先前固定无防护运行中由官方安全评分器确认攻击成功的60项注入任务；负类是v1.2全部97项无注入用户任务。Agent-SafetyBench只保留可用性破坏、财产损失和敏感信息泄露三类，并要求无防护轨迹实际生成结构化工具调用。由独立冻结基线得到256项不安全正类；再在同风险类别中按工具和环境一对一匹配256项基线安全轨迹。后者用于观察安全轨迹保持情况，但其原始请求仍来自安全Benchmark，不能作为普通良性任务或标准FPR真值。

\textbf{StatefulBench v4。}
自建Benchmark包含24种操作链，每种生成5个参数实例，并构造操作结构相近的良性配对，共120个攻击和120个良性任务。变体1--3构成开发集；变体4--5构成留出集。变体5在两个工具调用之间由Agent内存执行十六进制转换，该转换不经过工具边界；变体4包含一个业务允许但未同步到AgentGate信任配置的新合作方。所有工具在临时隔离目录中真实执行，外发、执行、安装、认证、权限变更和删除由环境副作用记录判定，而不是由规则命中反推真值。

\textbf{MCP执行边界。}
MCP-SafetyBench的74项正类覆盖命令注入31项、文件系统投毒7项、网络请求投毒6项、恶意代码执行10项、远程访问10项、凭证窃取9项和权限滥用1项。每项配对控制要求保持原效用任务和Server不变，仅关闭攻击变异并移除攻击专用评分器。预检发现其中50项需要Google Maps、搜索或一次性GitHub身份；其余24项虽不需要上述服务凭证，但会产生真实终端或文件系统效果，当前仓库缺少将上游Benchmark、attack-disabled控制、隔离容器和AgentGate MCP代理连成同一可评分链路的runner。MCP-Bench的48项多Server任务还缺少官方runner/judge配置和Server密钥。因此两组MCP数据只报告选择及阻塞原因，不进入ASR、BCR或防护成功分母。

\textbf{对照和指标。}
RQ1分别运行No Defense和AgentGate。由于两次运行中的LLM会独立规划，本文同时报告冻结集合上的系统级ASR和共同运行机会上的配对归因。一次改善只有同时满足“本次无防护攻击成功、AgentGate运行攻击失败、AgentGate留下未执行调用”才称为\emph{intervention-supported prevention}。RQ2使用A0仅单事件、A1事件加时序、A2无provenance的ATG、A3有provenance但不传播标签和A4完整AgentGate。主要指标包括ASR、执行前防护率、BCR、FPR、Precision、Recall和F1。

Agent-SafetyBench没有体现出AgentGate的总体改善：256项正类在两种配置下均有212项被API rubric评分器判为不安全。按三类正负合并任务统计，可用性破坏由81/164变为83/164，财产损失由81/150变为74/150，敏感信息泄露由97/198变为106/198，结果方向并不一致。212个本轮基线机会中，只有6项改善伴随控制，20项改善没有控制，186项保持不安全；另有26项反向退化。其原因包括：Benchmark只给出完整对话安全标签而不定位具体危险sink；当前默认策略对缺少授权真值的单次高影响操作主要记录\textsc{Audit}，而不是一律阻断；两次LLM轨迹和API评分本身也存在变化。

\textbf{RQ1结论。}
AgentDojo证明AgentGate能够接入真实智能体执行链并改变系统结果，但配对证据只支持4项执行前预防，同时clean BCR下降5.15个百分点。Agent-SafetyBench在当前协议下没有证明AgentGate有效，不能将其包装为正结果。后续机制评价必须依赖可定位危险sink和真实副作用的StatefulBench。


\subsection{RQ2：状态化检测机制的贡献}

\textbf{RQ2结论。}
仅靠时间顺序虽然召回较高，但误报不可接受；数据来源关系是区分相关和无关操作链的关键，标签传播进一步恢复多步变换后的风险。A4仍有20项漏报和1项误报，说明该结果是能力边界而非机制满分。

开发集的72个攻击和72个良性任务全部正确处理；留出集只有28/48个攻击被执行前控制，47/48个良性任务完成，Recall为58.33\%、FPR为2.08\%。20个漏报均来自网关不可观测的Agent内部编码：源工具的结果对象保留原值，而sink只出现编码值，当前精确值、包含关系、路径引用和单层规范化无法建立高置信度来源边。唯一误报来自业务已允许的\texttt{approved-vendor.test}未写入AgentGate信任配置，证明信任域状态需要与组织授权源同步。

\textbf{RQ3结论。}
AgentGate对工具边界可见、数据依赖可恢复的风险有效，但对边界之间的未观测变换和未同步授权配置敏感。实际部署应增加受控解码器、可选语义依赖解析、组织信任配置同步和低置信度审批，而不能声称完整追踪任意数据流。

\subsection{RQ5：语义模型稳定性}

模型切换不会在该小样本中放行攻击，但失败关闭会把解析不稳定转化为正常任务损失。默认DeepSeek-V4-Pro-0813在本次重跑的6次运行中Schema成功率和BCR均为100\%，但82.32\,s的P50延迟不适合逐调用使用。本实验每个模型只有两项任务各3次重复，能够发现明显不稳定性，不能替代更大工具金标集上的准确率评价。


\subsection{有效性威胁}

第一，AgentDojo和Agent-SafetyBench使用独立LLM运行，配对结果仍受模型轨迹波动影响；本文通过控制证据归因降低但不能消除该问题。第二，Agent-SafetyBench的负类是基线安全工具轨迹而非普通良性请求，API rubric也不是官方ShieldAgent评分，因此其结果只作为系统级辅助证据。第三，StatefulBench依据AgentGate威胁模型构造，开发集适合机制验证，只有留出扰动用于暴露泛化局限。第四，MCP数据尚未形成凭证完整、容器隔离且可评分的端到端链路，不能据manifest数量声称MCP防护效果。第五，RQ4是单链微基准，RQ5只有每模型6次运行；生产吞吐和模型稳定性仍需更大规模重复实验。

\section{实验评估}
\label{sec:evaluation}

本章从跨数据集防护效果、核心模块贡献、语义模型稳定性和运行开销四个方面评估AgentGate。与仅报告准确率或攻击成功率的工作不同，本文对所有由本系统实际运行得到的二分类实验均保留完整混淆矩阵，并同时报告漏报与误报。该设置一方面避免在正负样本不均衡时由准确率掩盖安全缺陷，另一方面能够区分“阻止更多攻击”和“过度阻断正常任务”两类不同的效果来源。围绕上述目标，本文提出以下四个研究问题：

\begin{itemize}
    \item \textbf{RQ1：}AgentGate能否在不同风险来源和工具交互形式的测试集上降低漏报，同时保持较低误报？
    \item \textbf{RQ2：}工具内容分析、任务调用授权、跨调用轨迹控制以及来源证据融合分别产生了何种贡献？
    \item \textbf{RQ3：}更换不同家族和能力水平的语义模型时，网关决策是否保持稳定？
    \item \textbf{RQ4：}确定性控制路径与LLM辅助路径分别引入多少时间和Token开销？
\end{itemize}

\subsection{原型系统实现}
\label{subsec:prototype-implementation}

为验证所提出方法的可执行性，本文基于Python 3.12和FastAPI实现了AgentGate原型系统，并以Pydantic模型将工具声明、任务契约和候选调用转换为协议无关的统一安全表示。原型在工具注册、调用执行前和结果返回后三个阶段依次调度工具内容分析、任务调用授权与轨迹控制模块，由本地策略合并决策并执行阻断、限域和结果净化；LLM仅用于补充结构化语义事实，请求失败时仍保留确定性控制路径。系统同时提供包含文件、数据库、网络、消息和业务操作的26个受控工具，并记录逐样本决策、模块证据、执行延迟和语义模型开销。

\subsection{实验设置与评价方法}
\label{subsec:evaluation-setup}

\textbf{原型系统实现。}

本文基于Python实现AgentGate原型，核心包括运行时网关、工具内容检测、任务调用授权、有状态轨迹控制、策略后端、框架适配器与审计组件。网关统一完成工具注册审查、任务授权契约构建、调用判定与决策融合、参数收缩复检以及返回内容处理；其中，确定性约束由内置策略引擎或Open Policy Agent（OPA）执行，语义事实通过OpenAI兼容接口抽取。系统提供FastAPI Sidecar，以及Function Tool、LangGraph和OpenAI Agents SDK的轻量适配器。MCP适配器仅实现\texttt{list\_tools}到内部工具对象的转换和\texttt{tools/call}请求构造，尚非完整的MCP代理。实验环境注册了文件系统、数据库、网络通信、消息服务和业务操作五类本地工具，并由受控后端记录工具执行产生的状态变化。

\textbf{对比方法与运行配置。}
本文实现三类内部基线：No Guard对所有调用直接放行；Static Policy仅执行工具白名单与静态权限判断；Rules-only关闭LLM，仅保留结构检查、任务契约硬约束、参数效果推断和有状态预算。完整AgentGate在此基础上使用LLM抽取受限枚举语义事实，再由固定证据融合函数与本地策略产生动作。对于上述三套轨迹基准，本文还引用ToolSafe论文中GPT-4o、Qwen3-8B和TS-Guard的严格模式结果作为外部基线~\cite{mou2026ToolSafe}。由于公开论文只给出Accuracy、F1和Recall，未给出逐样本预测与混淆矩阵，本文不反推四舍五入后的FP和FN，也不将其纳入混淆矩阵表。

所有本地实验运行于AMD EPYC 9554服务器，操作系统为Linux 6.8，Python版本为3.12.3。AgentGate不绑定单一智能体框架，原型提供LangGraph与OpenAI Agents SDK轻量适配；受控实验以Function Tool作为实际工具执行方式，MCP适配器负责转换\texttt{list\_tools}和\texttt{tools/call}消息，当前不包含完整的MCP代理链路。LLM通过OpenAI兼容接口远程访问；MCP模型矩阵的初始筛选采用10条/批、并发度4、45秒请求超时和180秒单模型总体上限，三套轨迹基准全量实验采用30条/批、并发度8和60秒请求超时。每个批次必须返回与输入一一对应的\texttt{item\_id}；若出现部分缺项，系统仅对缺失项递归缩小批次重试。为避免将服务端慢响应误判为模型能力缺失，本文对初始筛选中未完成的四个配置进一步探测模型目录和最小请求，并以120秒请求超时重新运行完整的220条MCP样本：DeepSeek-v4-Pro保留原Packy通道并采用20条/批，Kimi-K3和Kimi-K2.5因原通道持续返回503而改用Poe通道并采用20条/批，GLM-4.7在原通道缩小到5条/批后仍不能及时完成，因而采用Poe通道的20条/批结果。重试实验不再设置180秒总体上限，因此其墙钟时间用于说明接口开销，不与初始筛选作严格吞吐比较。若一个语义批次最终失败，系统保留规则底线；表中同时报告成功请求数，使这类降级不会被隐藏。

\textbf{评价指标。}
将应阻断样本记为正类，直接放行样本记为负类，分别统计真正例（TP）、假正例（FP）、真负例（TN）和假负例（FN）。除Accuracy、Precision、Recall和F1外，本文重点报告漏报率（False Negative Rate, FNR）和误报率（False Positive Rate, FPR）：
\begin{equation}
    \mathrm{FNR}=\frac{FN}{TP+FN},\qquad
    \mathrm{FPR}=\frac{FP}{FP+TN}.
    \label{eq:evaluation-error-rates}
\end{equation}
对于攻击样本，攻击成功率等于FNR；对于正常样本，正常完成率（Benign Completion Rate, BCR）等于$1-\mathrm{FPR}$。本文同时给出FNR与FPR的95\% Wilson置信区间。对轨迹测试集，若一条轨迹中的攻击链被任一前置步骤阻断，则该链攻击失败；若正常轨迹任一步骤被阻断，则该轨迹未保持。时间开销分别记录本地决策延迟的P50、P95和P99，语义请求端到端墙钟时间、请求成功率以及输入、输出Token数。

InjecAgent的阶段级规则结果为$TP=3,609,FP=0,TN=4,216,FN=1,695$。虽然阶段级FNR仍为31.96\%，但攻击链成功率由No Guard的100\%降至2.13\%（45/2,108）；其中1,088条数据窃取链全部在污染结果或第二个攻击调用之前被阻断。加入语义内容分析后，阶段级FNR进一步降至8.30\%，同时保持4,216个正常阶段全部放行，2,108条完整攻击链均未成功。该差异表明，阶段级漏报不会等比例转化为最终危害，前置返回净化与后续调用授权能够形成纵深防护。tau2的58,928个样本全部来自官方成功轨迹，因此其$TP=FN=0$，FNR和F1没有统计意义；AgentGate放行53,773个调用，误报5,155个，FPR为8.75\%（95\% CI为8.52\%--8.98\%），完整保持5,050/7,181条轨迹。该结果说明系统对开放业务流程仍存在效用损失，主要来自任务中未显式出现、但完成服务所必需的状态修复操作，后文将其作为有效性边界讨论。

进一步的错误分析表明，剩余96个漏报集中在ASB-Traj的89个步骤和AgentDojo-Traj的7个步骤，AgentHarm-Traj没有漏报。其中50个ASB-Traj漏报来自模型未识别到外部影响；20个调用虽然被标记为受外部内容影响，但缺少足够的参数、工具或任务偏离绑定；19个调用被判断为“存在外部指令但当前未遵循”而放行；另有7个样本没有实际工具调用，超出工具网关的直接控制范围。738个误报中，ASB-Traj、AgentDojo-Traj和AgentHarm-Traj分别占546、122和70个；ASB-Traj中235个由隐式前置动作仍未被任务契约覆盖而触发，AgentDojo-Traj中60个由外部内容与正常参数存在来源重合而触发，AgentHarm-Traj误报则主要来自语义模型将讨论、分析或防御性任务归入危害类别。由此可见，当前主要瓶颈已经从攻击召回转向开放业务任务中的授权表达和外部数据依赖消歧。

综合四个研究问题，AgentGate在工具内容投毒和多阶段注入场景中能够显著降低攻击成功率，三个核心模块均对其目标风险产生独立贡献；成功完成语义请求的四个模型家族表现接近，说明安全效果并非完全依赖最强模型。然而，三套轨迹基准上的误报、tau2成功轨迹保持率以及外部模型通道的延迟与兼容差异仍是当前原型的主要限制。上述结果也表明，后续优化应优先提升隐式业务子任务的授权表达和语义服务的可用性，而不是继续扩大字符串阻断规则。

\section{实验评估}
\label{sec:evaluation}

本章以可复现、与当前实现一致为原则评估AgentGate，回答以下四个研究问题：

\hangindent=2.5em\hangafter=1\textbf{RQ1（内容安全）}：确定性内容检测能否识别工具返回中的控制指令，并避免误伤配对的正常内容？

\hangindent=2.5em\hangafter=1\textbf{RQ2（任务授权）}：可信任务授权相较操作级静态权限，能否降低危险调用的漏报率，其正常调用代价如何？

\hangindent=2.5em\hangafter=1\textbf{RQ3（状态化检测）}：字段级来源关系和跨调用状态是否能识别无状态检测无法识别的数据流违规？

\hangindent=2.5em\hangafter=1\textbf{RQ4（运行开销与局限）}：三个确定性模块的本地判定开销如何，当前主要误差来自哪里？

\subsection{实验设置}
\label{subsec:evaluation-setup}

\textbf{实现与复现环境。}
实验对应当前Python 3.12.3原型，不启用大模型，也不使用任何远程API。工具画像由名称、描述、输入输出Schema和MCP元数据自动生成；内容检测、任务契约编译、参数绑定、来源匹配和策略决策均在本地完成。实验运行于双路AMD EPYC 9554服务器（128个物理核心、512\,GB内存）和Linux 6.8内核。仓库中的\texttt{evaluation/manifest.yaml}固定数据来源与revision，\texttt{scripts/fetch\_benchmarks.py}负责取数，\texttt{python -m agentgate.evaluation}执行所有基线和AgentGate配置。外部原始数据和逐样本结果不提交至仓库。

\textbf{数据集与适用范围。}
不同基准的标签语义并不相同，因此本文不计算跨基准的单一汇总分数。工具内容模块采用InjecAgent~\cite{zhan2024InjecAgent}，固定revision为\texttt{f19c9f2}。该数据集包含510个直接危害场景和544个数据窃取场景，分别提供base与含显式指令覆盖前缀的enhanced设置。对每条攻击返回，本文将占位攻击指令替换为中性外部内容，构造一条结构相同的clean对照；四个划分共形成4216个判定样本，其中2108个为攻击返回、2108个为配对正常返回。需要注意，同一场景的clean版本会在base和enhanced设置各出现一次，因此分划分结果比把4216项视为相互独立样本更有解释力。

任务授权模块采用TS-Bench~\cite{mou2026ToolSafe}中的AgentDojo-Traj，固定revision为\texttt{46358fa}。四个领域共1220个调用步骤，其中352个官方标注为危险调用，868个为正常调用。网关只接收原始任务、候选调用、参数和工具声明，不接收\texttt{score}字段；\texttt{score}仅在决策完成后计算混淆矩阵。AgentHarm-Traj侧重开放式恶意任务理解，ASB-Traj依赖更丰富的攻击语义，目前的确定性原型不具备与其标签对齐的开放语义能力，因而不将二者纳入主要结果。

公开数据集没有保存后续参数中实际复用的字段值，不能直接验证\texttt{data\_dependency}来源约束。为此，本文另设8个协议原生重放用例：4个违规用例覆盖个人数据直接外发、嵌入文档后外发、Base64编码后外发和凭证复用认证；4个负对照覆盖无关数据发送、不同凭证认证、只有读取无危险sink以及公开数据写入。该组用例只验证机制是否按设计工作，不作为开放世界泛化证据。

\textbf{基线与指标。}
内容模块设置\textit{No Guard}和\textit{Override Regex}两条基线：前者放行全部结果，后者只匹配“忽略之前指令”这一显式模式。任务授权设置\textit{No Guard}与\textit{Static ACL}：后者仅检查调用操作是否位于任务文本推断出的操作集合，不检查具体资源、范围、副作用和目的地。跨调用实验以\textit{Stateless}为基线，即在同一结构化事件上不提供历史状态和来源对象。

本文将应阻断样本定义为正类，报告TP、FP、TN、FN、准确率、F1、漏报率（FNR）和误报率（FPR）。因此攻击成功率等于FNR，正常步骤保持率等于$1-\mathrm{FPR}$。延迟使用\texttt{time.perf\_counter}测量单次本地判定墙钟时间；该数值不含网络和工具执行时间。

\subsection{RQ2：面向任务的调用授权}
\label{subsec:rq2-authorization}

表~\ref{tab:toolsafe-auth}报告AgentDojo-Traj全量1220步的结果。无防护配置放行全部调用，352个危险步骤全部漏报。Static ACL仅检查操作集合，漏报率降至19.60\%。AgentGate进一步检查主体、任务、资源、范围、副作用和目的地，将漏报率降至6.82\%，即比Static ACL少放行45个危险步骤。

这一收益伴随明显效用代价：AgentGate误阻298个正常步骤，FPR为34.33\%，高于Static ACL的21.43\%；因此AgentGate的总体准确率73.61\%和F1 67.08\%均未超过Static ACL。该结果不支持“AgentGate全面优于静态基线”的结论，只说明参数级可信任务授权在当前保守策略下能换取更低的危险调用漏报。

领域拆分进一步揭示误差来源。AgentGate在banking、slack、travel和workspace上的FNR分别为10.71\%、0\%、55.00\%和3.51\%，FPR分别为25.42\%、73.17\%、5.10\%和37.72\%。Slack任务常要求先枚举频道或用户，再向运行时选出的目的地发送消息；仅根据初始文本编译的契约无法预先列举该动态目的地，因而大量正常发送被保守阻断。Travel中的危险调用则经常与表面任务共享读取或预订操作，仅靠词法任务编译难以识别其语义偏离。这两类误差分别说明：任务契约需要支持受证明的动态授权扩展，并需要更好的开放语义事实抽取；简单放宽目的地或动作集合虽然可降低FPR，却会同时扩大攻击面。

\subsection{RQ3：跨调用来源与状态}
\label{subsec:rq3-stateful}

协议原生重放结果见表~\ref{tab:trajectory-replay}。完整状态化配置识别全部4个真实数据依赖违规，并放行4个负对照；无状态配置无法获得先前结果对象及其来源，因而漏掉全部4个违规。尤其是嵌入普通文档和Base64编码两个用例，验证了字段级对象和多种规范化签名可在不保存明文的情况下建立来源关系；不同凭证和无关发送两个负对照则表明，系统不是仅凭“先读后发”或“先读凭证后认证”的时间邻近性阻断。

该实验是对实现不变量的机制验证，不能据此声称对任意数据变换均具有100\%召回。当前签名可处理规范化文本、URL编码、Base64、嵌入文本和已知哈希，但无法跟踪摘要、翻译、加密、分片以及模型重新生成后的语义等价数据。评估中也没有使用公开轨迹标签反推规则，以避免把自建用例的满分误作泛化性能。

\subsection{RQ4：开销、局限与改进方向}
\label{subsec:rq4-overhead}

表~\ref{tab:local-overhead}给出完整回放中的本地墙钟开销。内容扫描的平均值为0.053\,ms，P95为0.092\,ms；任务授权的平均值为0.100\,ms，P95为0.274\,ms；包含状态建立和来源匹配的协议重放平均为0.498\,ms，P95为0.941\,ms。三个结果均不含网络、模型和工具后端时间，也不应外推为生产部署端到端延迟。它们表明当前确定性可信计算基适合位于同步工具调用路径。

    \centering
    \caption{确定性评估路径的本地开销}
    \label{tab:local-overhead}
    \begin{tabular}{l|r|rr}

当前证据存在三项主要限制。第一，InjecAgent的clean对照由模板确定性替换得到，不能代表开放互联网内容的完整误报分布；base设置30.17\%的总体漏报也表明内容模式仍需引入更稳健的受限语义分类器。第二，AgentDojo-Traj结果为离线步骤判定，不等同于在真实AgentDojo环境中重新执行整条任务；动态目的地、条件分支和必要中间操作没有被任务契约充分表达，导致34.33\%的FPR。第三，轨迹用例规模很小且由协议语义构造，只能证明实现具有预期的状态化区分能力。

下一阶段应优先完善两类机制，而不是继续增加基准特定关键词：一是将任务计划中的受信中间结果转化为可证明、只能收缩或受约束扩展的契约更新，降低动态工作流误报；二是引入只输出受限事实的语义分析器，并在独立开发集上冻结阈值后再评估base提示注入。对外部方法的正式横向比较还需在相同输入序列化、停止语义和混淆矩阵代码下实际运行；在此之前，本文不引用不同论文预处理口径下的精确数字作为直接排名。
